# Native Desktop feature matrix

## Desktop standards verification (2026-10-13)

Native dialog styles now share `src/main/desktop/src/ui/native-styles.ts`. Theme changes update
every semantic color role; About and update dialogs follow locale changes. Windows resize,
wrap and scroll with system fonts, visible focus, consistent actions, forced colors and reduced
motion. Update actions retain their labels, show inline progress and prevent duplicate clicks.
Native sign-in screens provide a main landmark and defined focus/destructive color roles.

Windows evidence: typecheck/build and all 138 Desktop unit tests passed; Maven unit tests passed
1510/1510 with `-Dskip.frontend=true`. The full Electron run passed 27 cases, failed two timing
checks and skipped the opt-in Windows registry-theme test. After fixture and close-acknowledgement
fixes, both failures passed in a 4/4 focused rerun covering client-role duplicate prevention,
Settings, native-window isolation and update dialogs. Chooser, About, Settings, Quick Access and
update windows passed Turkish/200% zoom, landmark and horizontal-overflow checks with background
screenshots. Update tests cover live theme/locale changes, forced-color emulation, keyboard focus
and Escape cancellation. Prettier passed for changed source files; `git diff --check` is clean.

Final local Windows NSIS, portable and AppX builds passed, followed by `pnpm smoke:package`:
native entry, config/version, safe-storage status, packaged artwork, redacted diagnostics and
hidden/unfocused windows. These are unsigned local checks. macOS/Linux runtime, actual assistive
technology, OS high contrast and signed release/update acceptance remain target-platform work.

All E2E launchers use `DESKTOP_E2E_BACKGROUND=true` and disable timer/frame throttling only in
test windows. The release workflow builds the native renderer once and shares its short-lived
artifact with platform jobs, which compile main/preload only. macOS builds separate x64/ARM64
packages together to preserve both architectures in updater metadata and checks both signatures
and notarizations. Workflow tests enforce renderer artifact reuse and reject universal packaging.

Status: `Complete` means acceptance evidence covers the requested native behavior;
`In progress` means the native slice exists but parity or platform evidence remains;
`Blocked` is reserved for missing backend/client registration where implementation
would otherwise require weakening security.

This matrix records Muharem's Desktop assignment from the Ownership split in
[`NATIVE-PLATFORM-PRD.md`](NATIVE-PLATFORM-PRD.md). The Web console remains the
reference implementation; the Electron native renderer owns its presentation and
uses typed, capability-scoped API calls.

## Client scope catalogue acceptance (2026-10-15)

The native Client scopes screen now presents aligned Name / Display name / Description / Actions
columns. Technical scope names open a keyboard-accessible detail page; row menus respect built-in
status and `manageClients` access. Search and sorting share one compact toolbar, and scope detail,
create, status badges, shared brand artwork, and the native menu use the shared desktop language
and theme tokens. Focus, pending search, long Turkish labels, both color themes, and 200% zoom are
covered by focused renderer tests and `e2e/client-scopes-visual.test.mjs`.

Same-window 1280 × 900 before/after screenshots and 200% zoom review captures are stored in
`src/main/desktop/e2e/artifacts/client-scopes/`. Windows native acceptance is complete for this
change; macOS and Linux menu and high-contrast validation still depends on those target platforms.

## Organizations list and create acceptance (2026-10-19)

Native Admin navigation shows Organizations only when `/api/admin/whoami` grants
`queryOrganizations` or `viewOrganizations`. The native list uses the bounded existing
`GET /api/admin/organizations` contract, supports search, name sorting and paging, and shows
the counts and enabled state returned by the backend. Create is visible only to
`manageOrganizations` or an administrator and uses the existing validated
`POST /api/admin/organizations` DTO. The Desktop adapter allows that exact POST and the bounded
list query; it rejects detail, update, delete, duplicate query parameters, unsupported sort and
out-of-range page sizes.

English/Turkish labels, field validation, inline create progress, duplicate submission blocking,
offline disabling, and the shared native 401/403/timeout handling are covered by
`test/native-organizations-parity.test.mjs` and `test/api-adapter.test.mjs`. The native renderer
does not import Web components. Organization detail and member/domain/invitation/group/provider/
claim management remain outside this list/create slice; macOS/Linux packaged evidence remains
open.
